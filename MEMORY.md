## Constraints discovered

- Orca terminals snapshot the environment at startup — a key added after Orca starts is
  invisible to those terminals, hence the Windows-User-Environment fallback in
  `resolveZaiApiKey()` (`src/core/zai-key.ts`) is read on every invocation, never cached.
- Standalone Claude Code installs expose `claude.exe`, not a `.cmd` shim — don't assume the
  shim exists when locating the binary (`src/core/claude.ts`).
- **A doctor-command test that doesn't inject `readUserEnvDiagnostic` silently falls through to
  the REAL per-user store reader**, which on this dev machine shells out to `powershell.exe` and
  reads the actual saved `ZAI_API_KEY`. This happened once (2026-09-22, see session log) and
  printed the real key into a Vitest failure diff that landed in an agent's tool output/transcript.
  Every `doctorCommand`/credential test MUST inject a fake `readUserEnvDiagnostic` (see the
  `baseDeps()` helper pattern in `tests/integration/doctor-command.test.ts`) — never rely on the
  default falling through silently in a test file.
